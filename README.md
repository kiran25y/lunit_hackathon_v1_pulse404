# Lunit FM L2 HealthBench Harness

Submission-oriented two-stage medical evidence harness for Lunit FM L2.

## Included

- Separate L2 retrieval and generation stages
- MCP execution with `cite_uid` capture
- Multi-turn state reconstruction and emergency hints
- Citation validation and one-pass L2 revision
- OpenAI-compatible adapter plus deterministic mock mode
- JSONL batch runner, tests, Dockerfile and submission checks

> Lunit's exact endpoint and MCP schemas are supplied on-site. Configure them in `.env`. If its API is not OpenAI-compatible, edit only `app/l2_client.py`. If MCP is not HTTP JSON-RPC, edit only `app/mcp_client.py`.

## 1. Setup

```bash
unzip lunit-healthbench.zip
cd lunit-healthbench
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Windows activation: `.venv\Scripts\activate`.

## 2. Run without credentials

```bash
python -m app.main doctor
python -m app.main demo
pytest -q
```

Mock mode validates plumbing; it does not estimate medical quality.

## 3. Configure Lunit FM L2 on-site

Edit `.env`:

```dotenv
L2_MODE=openai_compatible
L2_BASE_URL=https://REPLACE-WITH-LUNIT-ENDPOINT/v1
L2_API_KEY=REPLACE_IF_REQUIRED
L2_MODEL=REPLACE-WITH-EXACT-L2-MODEL-ID
MCP_CONFIG_PATH=config/mcp_tools.json
```

Copy `config/mcp_tools.example.json` to `config/mcp_tools.json`, then replace entries with official names, URLs and schemas. Never commit keys.

```bash
python -m app.main doctor
python -m app.main smoke
```

## 4. Run requests

```bash
python -m app.main ask --text "What is the Korean reimbursement standard?"
python -m app.main ask --input examples/conversation.json
```

## 5. Batch validation

Input JSONL has one object per line with `id` and `messages`.

```bash
python -m app.batch --input data/validation.jsonl --output runs/predictions.jsonl
python -m eval.structural_eval --predictions runs/predictions.jsonl
```

The dashboard is authoritative. Local evaluation checks operational structure, not hidden physician rubrics.

## 6. Ablations

Test separately:

1. `ENABLE_RETRIEVAL=false`, `ENABLE_REVISION=false`
2. retrieval on, revision off
3. retrieval and revision on
4. `RETRIEVAL_MAX_CALLS` at 4, 6 and 8

Change one variable per dashboard run. Record commit, config, score, errors and latency.

## 7. Final submission

```bash
pytest -q
python -m app.main doctor
python scripts/check_submission.py
git status
git add .
git commit -m "final HealthBench harness"
git tag final-candidate
git push origin HEAD --tags
```

Submit the exact GitHub repository/branch required by the dashboard and confirm its displayed commit SHA. The last dashboard submission is final.

## Rules preserved

- Final user answer is generated by L2.
- Retrieval uses L2 plus supplied MCP tools.
- Revision, if enabled, uses L2.
- Runtime makes no direct PubMed or external-data calls.
- Do not target individual HealthBench examples or hidden rubrics.
